# PBQL Design Decisions

The numbered decisions that shaped the language and library, made
during planning (2026-07-13 … 2026-07-16). Code, docs, and commit history
refer to them as D1–D17. All are implemented; this file records what was
decided and why. The normative spec is [language.md](language.md); the
property surface is the generated [data dictionary](data-dictionary.md).

| # | Topic | Decision |
|---|---|---|
| D1 | Operator precedence | SQL-like, high→low: property access/calls → unary `-` → `* /` → `+ -` → comparisons → `NOT` → `AND` → `OR`. Arithmetic operators are part of the language — cheap to support and needed for expressions like `shot.to.x - shot.from.x`. |
| D2 | Missing data (`omitted = unknown` is pervasive in insights) | SQL/Kleene three-valued logic: a property whose data is absent evaluates to `unknown`; any comparison/arithmetic with unknown is unknown; `NOT unknown = unknown`; `WHERE` selects only `true`. `exists(expr)` tests presence and is never unknown. Without this, `NOT shot.isVolley` would silently match shots where volley-ness is unknown. |
| D3 | Context clamping | `shots` units never cross rally boundaries. `secs` units may extend past rally start/end by at most N seconds (engine option `maxSecsBeyondRally`, default **3s**) and are clamped to [0, video end]. The duration literal `rally` ≡ the Shot Explorer's `numBefore=999` ("to rally boundary"). |
| D4 | Duration sign convention & min/max | Durations are **positive magnitudes** of lookback/lookahead (`CONTEXT BEFORE 2secs`); direction comes from BEFORE/AFTER alone (`-` is an ordinary operator; duration literals are non-negative). Mixed-unit `min()/max()` resolve each alternative **per selected shot** to a concrete magnitude, then compare **magnitudes** — `min` = smaller extension = cap, `max` = larger = floor — with the **same meaning for BEFORE and AFTER** (no timestamp asymmetry). `shots` units also add context *shots* to the result (SE's `isContext`); `secs` only stretches the time window. |
| D5 | Naming surface | camelCase curated properties; enum values as strings (`shot.type = "dink"`). `shot.num`/`rally.num` are 1-based (match SE's `rallyNum.shotNum` URLs); JSON output uses 0-based `rallyIdx`/`shotIdx` (matches SE input/insights). Both `shot.num` and `shot.sequence` (`"serve"|"return"|…`) exist. |
| D6 | Hitter-relative frame | `shot.from.x/y` (and `.to`, `.peak`) are in the hitter's frame: mirror world coords when the hitter is on the far side (y>22) so own baseline is y'=0, net y'=22; x' grows to the hitter's right. `absX/absY/absZ` give raw world coords. Shortcut deriveds are properties per D16: `shot.from.feetFromNearestSideline`, `shot.to.feetFromNearestBaseline`, `hitter.feetToKitchen`, `hitter.distanceToNet`. |
| D7 | Built-ins get context | The engine passes `EvalContext` (current game/rally/shot, options) as an implicit first argument to every built-in — user-visible signatures never mention it. |
| D8 | SELECT / AS | Optional `SELECT expr [AS "label"], …` clause (before FROM, SQL-style). Without SELECT → shot-list output. With SELECT → one row per selected shot (CSV/JSON rows). Aggregates (`count/avg/sum/min/max`) collapse to a single row; mixing aggregate and non-aggregate columns is an error (no GROUP BY — heavy analysis belongs in spreadsheets/SQL). `AS` is purely a column label; units are conversions, never labels. |
| D9 | Case & strings | Keywords case-insensitive (`from`/`FROM`); property names case-sensitive. Strings double-quoted with `\"` `\\` escapes. |
| D10 | `me` and names | `me` resolves via host-supplied `meta.myPlayerIdx` (app: auth uid → tagged player; CLI: `--me`). `player.name` from `meta.players[].name`. Queries using `me` against a game with no mapping → those predicates are `unknown` (D2) plus a warning. |
| D11 | Tags | "Tags" = the **player-tagging** data written by the host's `/user/tag` (`video.userData.sessions[s].players[p] = {uid, name}`) — the same host-supplied `meta.players` that backs `player.name` and `me` (D10). `shot.taggedWith("x")` tests the shot's hitter (allowed on any player ref: `myTeammate.taggedWith("x")`; function spelling accepted per D15/D16): if "x" contains `@` it's an **email — exact match, case-insensitive** (player slots store `uid`/`algoliaAddrId`, not raw addresses, so the host resolves email→identity); otherwise it's a **name pattern — case-insensitive with `*` wildcards** (e.g. `"Alex*"`). `hitter.name = "..."` remains plain case-sensitive equality; `taggedWith` is the fuzzy/identity-aware form. Shot/range-level tags (bookmarks, AI `shot.tags`) are explicitly future work. |
| D12 | Session numbering (source syntax superseded by D17) | Sessions are **1-indexed** everywhere users see them ("game 1", `sessionNum`, the `:N` source suffix) — matching every other user-facing place. Machine-facing JSON output keeps 0-based `sessionIdx` (matches SE URLs/insights internals); docs call out the off-by-one explicitly. |
| D13 | Insights format target | The engine supports the **latest insights major only (4.x)** — tested against current, tolerant of older 4.x minors via D2 unknown semantics. Multi-video queries **skip-and-report** videos with unsupported insights versions ("reprocess to include"). The registry is version-aware, so 2.x/3.x adapters are demand-driven backlog, not rearchitecture. The old moments-based v1.0.2 shape is out of scope. CV files: excluded — but the source/registry design must not preclude a later cv adapter. |
| D14 | Errors | All phases emit `{code, message, line, col, length, hint}`; the parser condenses nearley's expected-token set into friendly text; the analyzer suggests near-miss property names ("did you mean isVolley?"). Payloads are designed to enable one-round self-repair by LLMs as much as to help humans. |
| D15 | LLM-friendly aliases | Accept unambiguous dialect variants and canonicalize via the formatter: `<>` ≡ `!=`, `==` ≡ `=`, `sec`/`secs`/`seconds` and `shot`/`shots` in durations (the printer applies number agreement: `1 shot`, `2 shots`, `1sec`, `2secs`); keywords already case-insensitive (D9). Rejecting near-misses just wastes an LLM repair round-trip. Property names and enum values match the vocabulary of the PB Vision analysis guide and the Shot Explorer filters so models that read PB Vision docs write matching queries for free. |
| D16 | Calling convention | Hybrid. **Zero-arg derived values are plain properties** (`hitter.feetToKitchen`, `shot.from.feetFromNearestSideline`). **Subject predicates with arguments are methods** (`shot.taggedWith("Alex*")`, `shot.inHighlight("atp")`) — subject-first reads as English and makes `shot.` autocomplete exhaustive. **Subject-less utilities are functions** (`min`, `max`, `exists`, `abs`). The function spelling of any method (`taggedWith(shot, "x")`) is accepted as a D15 alias and the formatter canonicalizes to method form. D7 (implicit EvalContext) applies to methods and functions alike. |
| D17 | FROM sources are opaque strings (2026-07-15; supersedes D12's `video()`/`folder()` syntax) | `FROM` takes a comma list of **quoted strings only** — `FROM "83gyqyc10y8f", "games/*.json"`; AST `sources: [string]`. The strings are opaque to the language: each host interprets them. The app queries the video/session it is showing. The CLI applies one rule per string: vid-shaped `^[a-z0-9]{12}(:[0-9]+)?$` = pb.vision video with optional **1-based** session — fetched from production via the version-discovery endpoint (the public bucket denies anonymous listing) and cached locally without expiration — else existing file = one insights JSON, else existing directory = every `*.json` beneath it recursively, else a glob; a local file that looks like a vid is written `"./…"`. The `video`/`folder` keywords are gone (ordinary identifiers again). SE integration shares the query itself via the explore page's `?q=` param (`toShotExplorerURLs`) instead of translating results to filter params. |

Also decided (2026-07-13): omitted `CONTEXT` clauses default to **BEFORE 0 /
AFTER 0** (queries are explicit; SE injects its own 1/1 default when it
generates queries). Surface time properties (e.g. `shot.hitTime`) are in
**seconds** (float) — ms stay internal and in machine-facing JSON output.
